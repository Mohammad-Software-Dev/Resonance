# Engineering Proof Gates — Browser First

## A — Browser rendering foundation

Pass when Babylon WebGPU and WebGL2 fallback render representative 2.5D scene correctly, with gameplay-equivalent visibility and Tier M 60-fps feasibility.

## B — Precision controller

Pass when Run/Jump/Evade/coyote/buffer/air control are predictable and independent of render FPS.

## C — Attract/Repel prediction

Pass when shared client/server simulation produces responsive control and acceptable reconciliation at 150 ms.

## D — Moving anchors/platforms

Pass when deterministic parametric targets do not cause repeated visible snaps.

## E — Link/rescue

Pass when server-authoritative relationship remains readable and responsive at target latency.

## F — Four-player dedicated session

Proves:

- four unique players;
- Colyseus room;
- regional server placement;
- join snapshot;
- reconnect/browser refresh;
- server performance.

No two-player-only assumptions.

## G — Shared object authority

No duplication, tug-of-war or client-authoritative transform exploits.

## H — Echo

100-repeat semantic replay produces consistent intended result.

## I — Save / guest reward / session license

Atomic revisions, idempotent rewards and solo/cloud conflict handling pass crash/reconnect tests.

## J — Streaming/cache

Pass when opening and adjacent-room asset packages load/prefetch without simulation hitch, with content manifest/version correctness.

## K — World transformation

100 state-switch/save/load cycles reproduce correct geometry/collision/reward state.

## L — Vector Shift

No unstable prediction chain with Attract/Repel/Latch.

## M — Water sphere framework

No general fluid simulation; moving volumes remain deterministic and readable in 4P.

## N — Flux

Flux eligibility + follow-up movement agree client/server at 150 ms.

## O — Phase

State collision/re-entry safe; mixed-state 4P readable; late join correct.

## P — Invert

Relationship revision/current launch remains synchronized at 150 ms.

## Q — Four-player readability

Player can identify own target, hazard, Link, rescue, objective and Phase/relationship state at target VFX density.

## R — Full-toolkit input usability

Critical content does not require error-prone “ability piano.”

## S — Campaign-state graph

Every legal outcome set retains Crown route, Periapsis and at least two final configurations.

## T — Finale transaction

Pre-commit save, campaign-owner authority, guest vote, pending/completion state and crash recovery are atomic.

## U — Browser/Electron parity

Same content/simulation build produces equivalent gameplay timing in browser and Electron.

## V — Tier M 4P performance

Representative worst-case room/boss maintains target 60 fps and 60 Hz simulation, with server tick/bandwidth headroom.

## Risk disposition

A failed gate must be fixed, simplified, given a validated fallback or explicitly rescoped before dependent content scales.
