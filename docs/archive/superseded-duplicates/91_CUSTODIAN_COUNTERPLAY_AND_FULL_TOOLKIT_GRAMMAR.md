# Broken Transit Crown — Custodian Counterplay and Full-Toolkit Encounter Grammar

**Purpose:** Define how late-game content recombines the complete Resonance toolkit without creating input overload or unfair ability denial.

# Principle

The Crown tests **fluency**, not memory of new verbs.

A good Crown room asks:

> Which tools fit this changed situation?

It should not ask:

> Can you press all nine systems in sequence?

# Encounter budget

For a normal critical room:

- 2–3 primary mechanics;
- 1 optional optimization mechanic;
- 1 co-op/Echo layer;
- 1 enemy counter concept.

For a boss/setpiece:

- 3–5 systems may interact, introduced in phases.

# Ability role preservation

## Attract / Repel

Still the fastest direct force verbs.

Late game must not make them obsolete.

## Link / Echo

Still solves relationship/multi-actor problems.

Custodian interception adds risk, not removal.

## Latch / Orbit

Primary anchor traversal.

## Vector Shift

Correction and route expression.

## Flux

Makes inert tagged systems eligible.

## Phase

Changes player state occupancy.

## Invert

Reverses valid relationship.

# Recommended late-game combinations

## Rail Recovery

Flux dead clamp → Invert rail → Latch.

## Mixed-State Transfer

Phase to Resonant bridge → Link handoff → return Material.

## Counter-Suppression

Custodian suppresses anchor → Flux alternate → Vector Shift.

## Relationship Theft

Enemy captures environmental tether → Invert tether → Repel through new route.

## Phase/Flux Device

Flux Material-side control → Phase to operate Resonant receiver.

## Water/Current Remnant

Use old Observatory water volume or Loom current as momentum component, not as whole room theme.

# Anti-pattern system

Custodian response is based on semantic event history.

Track examples:

- AnchorCategoryUse;
- ProjectileReflect;
- LinkRevive;
- SameLaunchPath;
- SamePhaseBypass.

## Response thresholds

Responses should require repeated behavior, e.g.:

- 3 similar uses within encounter window;
- one explicit warning/scan before counter.

## Counter properties

Every counter must be:

- visible;
- temporary;
- specific;
- destructible/bypassable where appropriate;
- unable to eliminate all safe choices.

# Link seizure

## Allowed

- add temporary third-point tension;
- redirect environmental force;
- threaten break;
- delay revive.

## Not allowed

- silently damage teammate;
- permanently steal Link;
- force friendly fire without consent;
- invalidate solo Echo.

# Anchor suppression

Suppress:

- one tagged anchor;
- one category in a local field;
- one temporary route.

Never suppress:

- all anchors in a lethal gap;
- landing point after player is irreversibly committed without grace.

# Phase counterplay

Custodian may:

- seal one Phase route;
- create state-specific hazard;
- track phased entry.

Custodian may not:

- disable Phase globally;
- force unsafe materialization.

# Flux counterplay

Custodian may:

- quarantine one Fluxed object;
- require re-Flux;
- shield one eligible component.

Custodian may not:

- make eligibility rules inconsistent;
- silently change tagged metal into non-Flux object.

# Invert counterplay

Custodian can:

- reassert Normal relationship after telegraph;
- counter-Invert one system;
- lock one relationship temporarily.

Avoid Invert ping-pong with no player agency.

# Co-op grammar

## 2P

Pair naturally divides:

- control / traversal;
- state A / state B;
- pressure / objective.

## 3P

Third player gets:

- rescue;
- suppressor removal;
- flex routing;
- enemy control.

Avoid “two people play, third watches.”

## 4P

Use:

- two pairs;
- two lanes;
- sector responsibility that crosses mid-encounter.

Avoid permanent roles assigned at room entrance.

# Solo grammar

Echo handles one simultaneous actor.

Echo should not be required to:

- dynamically retarget;
- make combat decisions;
- maintain multiple long recordings.

# Readability priority

1. player safety;
2. active countermeasure;
3. valid route/anchor;
4. teammate Link/rescue;
5. objective;
6. decorative late-game spectacle.

# Input-load rules

Do not require more than one context-sensitive late ability selection under sub-second timing.

Examples:

Good:

- Phase through barrier, then after landing Flux control.

Bad:

- midair Flux + Phase + Invert three separate targets inside 400 ms.

High-skill optional routes may compress timing, never baseline critical route.

# Loadout/build interaction

Core/Modules should provide advantages but no critical room requires a specific build.

Late-game enemies should not hard-counter an entire Core family.

# Difficulty tuning

Increase difficulty by:

- route adaptation;
- multi-lane pressure;
- overlapping but readable telegraphs;
- faster decision-making;
- responsibility sharing.

Do not rely primarily on:

- damage inflation;
- HP inflation;
- ability cooldown inflation;
- long resets.

# Telemetry

Track:

- ability usage by room;
- unused abilities;
- counter triggers;
- repeated-pattern frequency;
- failed target selection;
- co-op idle time;
- Echo re-records;
- input-conflict errors.

# Acceptance criteria

- full toolkit feels cohesive;
- old abilities remain valuable;
- counters create improvisation rather than frustration;
- no critical room becomes “ability piano”;
- solo and 4P share conceptual solution;
- input budget remains viable under combat pressure.
