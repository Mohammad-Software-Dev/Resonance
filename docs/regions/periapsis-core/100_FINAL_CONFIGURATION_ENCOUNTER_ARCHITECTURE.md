# Final Configuration Encounter Architecture

**Purpose:** Define four mechanically and emotionally distinct finale encounters without building four unrelated games.

## Shared production principle

The final chamber and some systems may be reused.

The **objective, topology pressure, opposing forces and emotional meaning must differ** by configuration.

Do not reskin one boss with four colors.

# 1. Historical Continuity — Continuity Encounter

## Objective

Re-establish Anchor Zero as centralized coordinator while preventing cascading overload.

The party must preserve:

- core transit bus;
- power spine;
- thermal spine;
- historical orbital correction loop.

At the same time, distributed Resonant/Tessel manifestations spill into systems being narrowed or disconnected.

## Encounter identity

**Preserve infrastructure while containing uncontrolled field propagation.**

## Mechanics

- seal unstable Resonant branches;
- defend central buses from overload;
- Phase into spillover zones to reroute/close them;
- Invert runaway correction tethers;
- use Link to synchronize historical control nodes.

## Opposition

Not a villainous Tessel monster.

Opposition comes from:

- unstable field manifestations;
- residual autonomous systems;
- infrastructure overload;
- optional Tessel defensive response if communication is open.

## Cost made mechanical

Some regional support nodes must be deliberately disconnected from central control.

Player sees which systems will lose access before commit.

# 2. Distributed Meridian — Distribution Encounter

## Objective

Break Anchor Zero's remaining master-control dependencies and keep regional Anchor networks stable while central systems shut down.

## Encounter identity

**Survive decentralization.**

## Mechanics

- sever master lines;
- stabilize multiple regional buses;
- allow selected central systems to fail safely;
- route temporary support between regional nodes;
- use Link/Echo as distributed control metaphor.

## Opposition

- collapsing historical systems;
- reasserting master-control routines;
- structural cascades;
- isolated Custodian emergency scripts.

## Cost made mechanical

Players must choose which 1–2 historical high-capacity systems are allowed to go dark permanently.

Choice is factual and visible.

# 3. Open Resonance — Resonance Encounter

## Objective

Integrate Tessel field intelligence into Periapsis without allowing either human control or distributed field behavior to dominate destructively.

## Encounter identity

**Establish shared regulation under uncertainty.**

## Mechanics

- maintain mixed Material/Resonant topology;
- route Signal Tokens between human and Tessel nodes;
- protect opt-out isolation channels;
- stabilize rapidly changing field relationships;
- respond to Tessel-generated patterns from validated authored sets.

## Opposition

- incompatible control assumptions;
- Custodian containment remnants;
- unstable Tessel manifestations;
- synchronization failures.

## Cost made mechanical

Some systems are deliberately moved into Tessel-regulated state and become unavailable to ordinary human-only control.

Some communities' opt-out channels reduce network reach.

# 4. Bounded Accord — Accord Encounter

## Objective

Create hard partitions between:

- human conventional control;
- Tessel field control;
- regional Anchor autonomy.

Then permanently disable Anchor Zero's ability to become master controller again.

## Encounter identity

**Build coexistence by destroying the possibility of total control.**

## Mechanics

- construct three partition rings;
- maintain bounded cross-state Links;
- route limited Signal Tokens through approved bridges;
- use Invert to prevent one partition from absorbing another;
- deliberately sever Anchor Zero master buses.

## Opposition

- Anchor Zero recovery routines;
- Tessel manifestations resisting segmentation;
- Custodian emergency scripts trying to recenter control;
- resource shortfall because peak capacity is reduced.

## Cost made mechanical

The party must destroy/decommission the final master-control conduits.

This is irreversible and visibly reduces maximum correction reserve.

# Shared structure

All four encounters use:

- short pre-commit checkpoint;
- 3 broad phases;
- fast retry;
- no long dialogue replay;
- party mechanics that scale by responsibility.

# 1–4 player matrix

## Solo

Echo owns one simultaneous support role.

## 2P

Each player owns one major subsystem/branch.

## 3P

Two subsystem roles + one mobile stabilization/rescue role.

## 4P

Two pairs or four partition/sectors.

No path gives guests only add-clear duty.

# Difficulty

Final encounters should be hard but clear.

Avoid:

- superboss timing;
- hidden one-shot mechanics;
- mandatory optimized build;
- excessive HP.

The challenge is decision execution and system coordination.

# Accessibility

Every finale supports:

- incoming damage scaling;
- timing-window expansion;
- target assist;
- visual-state enhancement;
- reduced VFX;
- reduced camera shake;
- Echo timing assistance.

Ending availability never changes because an assist is enabled.

# Shared assets allowed

May reuse:

- Periapsis chamber;
- Anchor Zero buses;
- Signal nodes;
- regional support pylons;
- party staging ring;
- selected enemy/manifestation actors.

Must differ:

- objective logic;
- active topology;
- subsystem priorities;
- encounter VO/narrative;
- final commit animation;
- epilogue state.

# Acceptance criteria

- four finale paths feel meaningfully different;
- each path's cost is expressed through gameplay before the commit;
- no path is framed as authorial “correct answer”;
- Bounded Accord remains costly;
- 1–4 player structures remain active;
- production reuse stays practical.
